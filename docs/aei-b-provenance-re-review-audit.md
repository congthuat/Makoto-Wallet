**Review baseline:** `cad9fc3424cc53b3a5d343473e6b567ab25322e7` on `phase12h-planner-strategy-integration`, clean worktree and index. **Finding:** material trust-source defect; AEI-B remains IMPLEMENTED / PENDING REVIEW, **not READY_TO_CLOSE**. AEI-C and Phase 13 remain NOT STARTED.

## Reproduction before the fix

An arbitrary caller supplied a plain object containing its own request/session IDs, plan, legacy resolution, and purported structured user event for `SEND 10 EURC`. It computed the exact request, plan, event, field and evidence-set digests using the public deterministic rules. No trusted user-input boundary ran. `createPlannerParameterEvidence` returned `FIXED_USER_INPUT`, and `compilePlannerStrategy` returned `COMPILED`. The focused regression failed with actual status `COMPILED`. A recomputable digest proved consistency among caller-controlled values, not the origin of the user's choice. The prior positive test fixture had the same authority shape and was not isolated by a production-enforceable trust boundary.

Production import search found no caller of `compilePlannerStrategy`, `createPlannerStrategyBindingV2`, or `createPlannerParameterEvidence` outside the Planner/AEI modules and tests. There is also no production structured Planner confirmation capture. Lack of a current caller limits reachability today but does not make the exported public factory an authenticated source.

## Scoped fail-closed fix

Runtime commit `e66b2f8a8b82dfb34ca1cc300f50537da2951567` makes `createPlannerParameterEvidence` structural only. With no structured event it emits `UNVERIFIED` nonfixed records. With a caller-supplied event it returns `UNVERIFIED` failure; no public function in the present repository mints `FIXED_USER_INPUT`. A provider claim remains rejected by 11D's closed proposal schema. A handcrafted v2 fixed result, including matching digests, fails `validatePlannerParameterEvidence`; AEI-B rejects it as `INVALID_PARAMETER_EVIDENCE`. AEI-A v2 creation/validation also fails because it revalidates the same source. Legacy `RESOLVED` and v1 compiler inputs still fail the AEI-B gate. V1 AEI-A binding remains a structural historical data contract and cannot satisfy AEI-B's v2 input.

This deliberately removes the positive compile path used by the earlier test fixture. Fixture data and a plain event object cannot prove a real user action. A later approved trusted input boundary must establish origin authenticity before fixed Planner parameters can compile. This review does not implement that boundary, a confirmation UI, or AEI-C. **AEI-B is not ready to close** while its intended positive fixed-value path has no trusted source.

Six dynamic request classes (previous output percentage, all received, receipt, previous transaction, quote and runtime balance percentage) do not compile a proposed fixed fallback. Plain-language `Send 10 EURC` remains `UNVERIFIED`. Request/session/plan/goal/key/value, source, and digest substitution tests fail closed where evidence carries those fields; nonfixed evidence intentionally carries no authoritative value.
