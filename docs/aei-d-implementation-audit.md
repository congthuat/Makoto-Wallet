## Implemented boundary

`frontend/lib/aeiDOrchestration.ts` exposes a host-ports factory, one-ACTION `orchestrate`, versioned account/read/quote/prepared/policy evidence and `AEIDOperationalEnvelopeV1`, plus a live validation function. It calls `validateStrategyMaterialization` against the retained live AEI-C input before wallet/provider access; this revalidates the private B2 source, AEI-A v2 binding and exact AEI-B recompilation. A loose descriptor, copied B2 source, replayed/caller-rehashed materialization or foreign ACTION cannot become input authority. The host supplies the existing `WalletReadContext` and `AgentContextSnapshot` together with read-only Phase 8 service ports. The two wallet observations must agree on connected account, wallet kind and verified Arc chain; the snapshot is bounded to 30 seconds. The host port is an application trust boundary, not cryptographic authentication against arbitrary compromised same-origin code.

One currently eligible ACTION is selected by exact step ID; a dependency edge returns `DEPENDENCY_BLOCKED` until a later verified prior-action contract exists. D never claims completion or derives a runtime amount from an order edge. SEND acquires wallet/network/live balance, a fee-aware Arc quote, then unsigned preparation. SWAP additionally acquires live Xylo-router allowance and an explicit supported slippage choice, a fresh USDC/EURC Xylo quote, then unsigned finite-approval/swap preparation where required. Direct CCTP BRIDGE returns `HANDOFF_REQUIRED` for an exact-account recipient, or `UNSUPPORTED_ACTION` for the unsupported Agent recipient shape, before an executable artifact; Circle App Kit Agent PREPARE remains unsupported. No bridge source receipt is treated as destination completion.

The existing `runPrepareTool` now offers observation-only `onValidatedQuote` and `onValidatedBalance` callbacks so D can bind the **actual internally refreshed quote and balance**. The existing prepare result remains unsigned, unsubmitted and `executionEnabled: false`; the callbacks are not wallet capabilities. D verifies the quote fingerprint, compares the internal balance to before/after reads, and rereads allowance after preparation. A changed account/chain/session snapshot, balance or allowance returns revalidation; a stale/changed quote returns requote or quote-stale. D invokes the existing `evaluatePolicy` **after** validated preparation because that evaluator requires the prepared result. It keeps BLOCK > REQUOTE > REVALIDATE > REQUIRE_REVIEW > WARN > ALLOW and never treats ALLOW as wallet consent or final-policy approval. The separate `evaluateFinalPolicy` fee/simulation gate and explicit wallet Review are later boundaries.

All evidence wrappers bind AEI-C digest/revision, ACTION/goal, account-context digest, chain, request and result digests, source/tool/provider data and freshness. Canonical content digests use domain separation, sorted object keys and lossless decimal bigint encoding. Digests are integrity/correlation only: D does not accept caller-supplied read, quote, preparation or policy results. A private runtime registration plus current host context and fresh live AEI-C revalidation is required by `validateAeiDOperationalEnvelope`; a copied or rehashed wrapper fails. This is application-level trust and does not defeat arbitrary same-origin compromise. The envelope is `OPERATIONAL_ONLY`, `executionEnabled: false`, `executionAuthority: FORBIDDEN`; it retains the whole materialization, dependency graph, typed status, warnings and unmet requirements for AEI-E/F without granting state or wallet authority.

Provider credentials stay in server-owned ports and are never fields in D evidence. Swap gas and Bridge source gas remain `not-estimated`; a protocol fee is not an authoritative gas estimate. The paid Planner route remains **DEPLOYMENT_GATED_BY_AUTH_AND_RATE_LIMIT** for absent server-side account authentication and distributed rate limiting. The approved post-AEI-G “Bản thử nghiệm 1” Surf port, canonical integration, QA, deployment and Phase 13 order remain deferred.
